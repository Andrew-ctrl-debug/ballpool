# Ball Pool на Three.js — пошаговый туториал

Этот проект воспроизводит интерактивную анимацию шаров, как на сайте Эрика Шевченко
(https://erik-shevchenko.com/), но **упрощённую**, чтобы её было легко понять новичку.

> ⚠️ Оригинал использует новейший WebGPU-рендерер Three.js (r185) + сложные
> эффекты (SSGI, temporal AA, анимации триггерные от текста). Мы делаем
> **классический WebGL-вариант** на том же логическом ядре: шары, гравитация,
> столкновения, реакция на курсор. Логика почти та же, но код в разы проще.
> Когда освоишь этот вариант — сможешь разобрать и оригинал.

---

## Как запустить

ES-модули (import/export) **не работают** при открытии `index.html` простым
двойным кликом (браузер блокирует импорт по `file://`). Нужен локальный веб-сервер.

Варианты (подойдёт любой):

```bash
# Если есть Node.js / npx
npx http-server . -p 8080

# Если есть Python 3
python -m http.server 8080

# Проще всего: открой папку в VS Code и нажми «Go Live» (расширение Live Server)
```

Затем открой в браузере: `http://localhost:8080`

## Пошаговый разбор (как это собрано)

### Шаг 1. HTML-каркас (`index.html`)

Ключевая идея — **два слоя**:
- `<canvas class="hero-canvas">` — сюда Three.js рисует 3D-шары,
  он позиционирован `absolute` и занимает весь блок.
- `<div class="hero-source">` — текст (заголовок, ссылки), лежит **поверх** канваса
  (у него выше `z-index`).

Шары поэтому «плавают» за текстом. У элементов текста стоит атрибут
`data-hero-obstacle` — намёк на будущую фичу «препятствия» (см. Шаг 7).

### Шаг 2. Сцена, камера, рендерер, свет (`setup.js`)

Базовые объекты Three.js, которые нужно знать:

| Понятие  | Что это |
|----------|---------|
| **Scene**  | «мир», куда кладём все объекты |
| **Camera** | точка зрения (мы используем перспективную) |
| **Renderer** | превращает 3D-сцену в картинку на канвасе |
| **Mesh**   | видимый объект = Геометрия (форма) + Материал (цвет) |

Свет (без него шары были бы плоскими):
- `PointLight` сверху-спереди — главный источник
- два `PointLight` по углам — чтобы не было чёрных зон
- `AmbientLight` — равномерное фоновое свечение

### Шаг 3. Шары через InstancedMesh (`field.js`)

Один `Mesh` — это один объект. Но нам нужно **300+ шаров**. Если создать
300 отдельных Mesh, браузер будет рисовать их по одному (медленно).
Решение — **InstancedMesh**: один геометрический объект, но с N копиями,
которые отрисовываются за один вызов (быстро). Это и есть магия производительности.

```js
const mesh = new THREE.InstancedMesh(ballGeo, ballMaterial, COUNT); // COUNT = 260
```

Каждому экземпляру мы задаём свою позицию и размер через матрицу
(см. `drawField()`).

### Шаг 4. Физика (гравитация + столкновения)

У каждого шара храним:
- **p** — позиция (`Vector3`)
- **v** — скорость (`Vector3`)

На каждом шаге (`stepField`):
1. **Гравитация**: `v.z += 9.8 * dt` (пол у нас — передняя плоскость `z = frontZ`)
2. **Движение**: `p += v * dt`
3. **Столкновения между шарами**: для каждой пары, если они пересеклись —
   раздвигаем и обмениваем импульс.
4. **Стенки**: не даём шарам вылететь за границы комнаты.

Мы используем **фиксированный шаг** 1/120 сек (вместо ежекадрового изменчивого `dt`),
чтобы физика была стабильной и предсказуемой. Время накапливается в аккумуляторе
(см. `loop.js`).

> В оригинале вместо двойного цикла используют пространственную решётку
> (grid), чтобы не сравнивать все 300×300 пар. Для 260 шаров двойной цикл —
> отличная отправная точка; решётку добавим потом.

### Шаг 5. Реакция на мышь (`input.js` + `field.js`)

- Слушаем `pointermove`/`pointerdown` на hero-блоке.
- Переводим координаты курсора в **нормированные** (-1..1).
- Создаём **луч** (Raycaster) из камеры в точку курсора.
- Для каждого шара ищем ближайшую к позиции шара точку на луче;
  если шар рядом — толкаем его *от* луча (сила пропорциональна близости).
- По клику (`burst`) — добавляем сильный «взрыв» и подброс шаров.

### Шаг 6. Игровой цикл (`loop.js`)

Анимация в браузере работает через `requestAnimationFrame` — браузер вызывает
функцию ~60 раз в секунду. Внутри:
1. считаем время между кадрами,
2. накапливаем время и запускаем физику по 1/120 сек,
3. рисуем (`renderer.render`),
4. просим браузер вызвать нас снова.

### Шаг 7. Отпугивание шаров от текста (препятствия) — «как это улучшить»

На оригинальном сайте шары **обходят текст**. Мы подготовили почву:
у элементов есть `data-hero-obstacle`. Чтобы реализовать:

1. Для каждого текстового элемента получить его прямоугольник
   (`getBoundingClientRect()`) и перевести в координаты комнаты.
2. В `stepField()` добавить проверку: если шар попал в прямоугольник —
   вытолкнуть его к ближайшему краю и добавить импульс (как делает `repelInterface`
   в оригинале).

Это следующий шаг, когда захочешь усложнить проект.

### Шаг 8. Полировка (glow-эффект и тень)

- У части шаров можно сделать **светящийся** материал (`emissive`)
  и повесить рядом маленький `PointLight` — получится «неон» (так сделано в оригинале).
- Включённый `shadowMap` даёт мягкие тени — но на 260 шаров он тяжёлый,
  поэтому на слабых устройствах лучше отключить.

## Главные идеи на будущее

1. **Scene → Camera → Renderer → Mesh**: этот минимум нужен для любой Three.js-сцены.
2. **`requestAnimationFrame`** — сердце любой анимации.
3. **Физика = позиция + скорость + фиксированный шаг по времени**.
4. **InstancedMesh** — как рисовать тысячи объектов быстро.
5. **Raycaster** — как «поймать» мышь в 3D.
6. **IO**: раздели код на модули (сцена / физика / ввод / цикл) — так проще расти.
